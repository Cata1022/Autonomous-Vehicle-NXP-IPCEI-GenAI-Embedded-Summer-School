Scoping Brief: Autonomous Car

Status: Ready for Requirements Engineering

Intended User: Third-year Computer Science student

1. Project Summary

A self-driving rover that pairs an ESP32-S3 CAM for vision and AI with the NXP FRDM-MCXA153 for robust motor control and obstacle avoidance. The project demonstrates a distributed processing architecture for edge AI robotics.

  • Main Objective: Navigate autonomously in a controlled environment by keeping within a lane and recognizing traffic signs, while avoiding obstacles.
  • Core Behavior: The ESP32-S3 processes camera feeds for lane keeping and traffic sign recognition, sending steering and speed commands via UART to the NXP FRDM-MCXA153. The NXP board drives the motors and autonomously stops if its local distance sensors detect an obstacle.

2. Fixed Platform Requirements

  • Main Board: NXP FRDM-MCXA153 (NXP MCXA153 MCU) Mandatory
  • Logic Level: Assume 3.3V logic unless verified otherwise.
  • Pin Policy: Use generic capabilities (UART, PWM, GPIO) unless specific pins are designated.

3. Project Ambition Tiers

Core Student Version Beginner

A basic autonomous rover relying purely on the NXP FRDM-MCXA153. Instead of the ESP32 camera, it uses simple analog IR line-tracking sensors for lane keeping and an ultrasonic sensor for obstacle avoidance.

  • Features: IR-based line following, Ultrasonic obstacle avoidance, DC motor control via PWM.

Recommended Summer School Version Intermediate

Integrates the ESP32-S3 CAM for classic computer vision. The ESP32 extracts lane lines using thresholding and sends steering commands via UART to the NXP FRDM-MCXA153, which manages motors and distance sensors.

  • Features: Camera-based lane tracking, UART communication protocol, Reactive obstacle avoidance.

Advanced Extension Advanced

Adds TinyML object detection on the second core of the ESP32-S3 to recognize traffic signs (e.g., STOP, arrow). High-confidence detections trigger override commands sent to the NXP MCU.

  • Features: Edge AI / TinyML inference, Asynchronous dual-core processing, Priority-based command handling.

5. Risks & Considerations

  • Voltage/Power: 5V logic sensors (like typical HC-SR04) require level shifting for the 3.3V NXP MCU. Motor noise and high current draw can brown out the microcontrollers.
  • Technical: UART message corruption between MCUs, or latency in processing TinyML on the ESP32 causing missed frames.
  • Safety: A physical kill switch (Start/Stop button) is required to safely disable the rover.

6. Open Questions & Assumptions

  • Assumption: The rover platform operates using differential drive or Ackermann steering.
  • Open Question: What exact motor driver IC is being used? This dictates PWM requirements and current capabilities.
